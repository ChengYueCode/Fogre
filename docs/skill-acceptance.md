# Forge 验收说明

本页是公开验证摘要，内部历史日志和机器路径不随源码发布。过去的本机安装、浏览器和原生编辑器记录不是新版本远程发布或真实学习效果的证明。

## 可复现检查

从完整源码根目录使用 Node.js ≥20 与 npm：

```sh
node scripts/build-entries.mjs --check
npm run check:links
npm test
npm run prepare:release -- --out dist/release-candidate
npm run verify:release -- --verify dist/release-candidate
```

`npm test` 为分发测试提供 npm 执行上下文；直接使用 `node --test` 跑全部文件缺少该上下文时，真实 npm 分发测试会失败。测试在独立临时目录建立档案，合成作答不进入真实学习档案。

## 证据与边界

### 2026-10-12：脚本输出位置与技能描述一致性

已核对学习 CLI、npm 包入口、构建/服务/档案/索引写入层与浏览器导出，以及安装、生成和发布脚本。工具与模板位置由技能目录决定；学习路径参数按命令执行工作目录解析。学习目录必须显式提供 `--out`，默认索引为命令工作目录的 `learning/learning-index.json`；外部 `--out` 不自动搬迁索引。`import --state` 是输入，合并结果写入 `<out>/state.json`；`export` 必须给 `--to`，只有省略 `quality-template --to` 才是终端骨架预览。完整合同见[输出位置](../skill/forge/references/output-paths.md)。

代码现在拒绝学习写入目标位于自身或其他 Forge 技能目录内，覆盖外置档案、导图、导出文件、草稿与索引，以及目录链接指回技能内部的情况；在 CLI 创建输出或锁前检查，构建/服务/共享写文件层也检查。读取随包模型仍可用；输入模型的协调锁不属于学习数据输出，锁协议与已有存储标识保持不变。

五组新增公共路径回归全部通过，实际覆盖 16 个学习写命令、外置写入目标、跨工作目录、绝对路径、npm 包入口、索引指针、导入输入不改写与核心构建/服务的保护。全量 **551 项，550 通过、0 失败、1 项真实历史工具检查跳过**。带工具的四个独立入口由生成器同步相同脚本与路径合同；136 个生成文件一致，82 个 Markdown、256 个相对链接无断链，六个技能格式校验通过。

本轮记录针对开发源码、生成入口及隔离分发；未升级个人已安装技能，不能将源码校验当作旧安装件已经获得新保护。

### 2026-10-12：入口与参考依赖优化

主技能入口从 7,482 字符、102 行缩至 3,243 字符、62 行，以范围判定、条件路由、执行等待、保存交付组织。独立整理的参考从 26 份减至 13 份，独立复核从 26 份减至 5 份；目录登记、失败恢复、构建输出与幂等合同分别由共享参考唯一维护，原公开章节锚点保留。五个独立入口及 UI 提示继续由同一生成器生成。

本轮全量检查为 **546 项，545 通过、0 失败、1 跳过**；跳过仍是未提供 `EMBER_OLD_TOOL` 的真实历史工具检查。最终分发检查 **5/5**、入口检查 **6/6** 通过；128 个生成文件同步，77 个 Markdown 文件、248 个相对链接无断链，六个技能格式校验通过。正向可达性检查覆盖每个技能入口到全部随包参考，另检查搬迁章节的原锚点。

测试期间曾出现安装件带入源码活动锁后误报占用的问题。安装器现在只排除 `.ember-lock` 与 `.ember-lock.recovery`；独立夹具确认这两份源文件保持原样，普通资源与相似文件名仍完整安装。修复前的失败与修复后的全量结果分别保留，不以复跑代替回归验证。

在隔离项目通过 Codex CLI 加载项目内入口规则：主技能首轮提出生活情境诊断并等待；提问入口只问一个问题；复核在零作答时返回正常空态；复习在无轮次时返回无法生成本轮计划；洞见在空记录时不把作者参考当成学习者理解变化。后四个只读检查未新增作答或掌握证据。主技能这里只验证了首轮响应，未验收模型/轮次建立与完整持续学习。

整理入口的初次 Agent 会话在 210 秒上限内未结束，但已生成学习页、原生导图、SVG 与来源/缺口记录。产物另经模型校验、档案读回和实际浏览器打开检查，显示提供的三条笔记与“掌握未知”，作答及掌握证据为空。后续只读交付会话也在 120 秒上限内未结束；两次超时均不算完整 Agent 调用通过。整理产物的工具与浏览器检查通过，完整调用仍未验收。这些检查不证明所有宿主的技能菜单发现，也不证明真人学习效果。

自主审查按规范与需求两条轴进行，已补齐独立复核的重建合同并加强必要规则、可达性、锚点及源锁排除检查。审查代理的模型接口报错、CLI 审查超时不计为审查通过；最终结论以完成的独立审查与实际复核证据为准。

| 验证层 | 能证明什么 | 仍需分别核对 |
| --- | --- | --- |
| 源码测试 | 归档、练习身份、协助、修正、复核、缓存合并与调度规则 | 真实学习者的长期学习效果 |
| 真实 npm pack、隔离安装和 CLI 构建 | 包文件、安装入口与脱离源码位置的运行能力 | npm registry 发布与所有宿主兼容性 |
| 干净源码快照、ZIP 与 SHA-256 读回 | 白名单、文件一致性、分发完整性 | GitHub 远程文件与 Release 下载 |
| 历史浏览器与原生导图验证 | 当时版本的保存、重开和图形往返路径 | 新版本完整 UI 验收、直接 file:// 路径与实时 MCP |
| GitHub Actions 配置 | 提供 Windows/Linux、Node 20/24 的可执行验证流程 | 真实远程运行结果 |

旧档案迁移用例正常执行；“真实旧工具拒绝升级档案”的专门检查需提供 `EMBER_OLD_TOOL`。当前未提供真实历史工具，这一项跳过。示例目录的旧 v1 备份已过时，不纳入公开快照；它不能充当当前示例的恢复入口或旧工具夹具。

公开源码、个人技能安装、会话发现、远程下载安装和正式发布分别记录。当前兼容范围见[环境支持](support.md)，首发步骤见[发布检查](release-checklist.md)。

## GitHub 首发验证

仓库 [ChengYueCode/Fogre](https://github.com/ChengYueCode/Fogre) 已公开上传，GitHub 识别 MIT，公开文件树与本地白名单一致。Skills 1.7.2 从真实远程仓库隔离安装主技能成功，安装内 LICENSE 与随包模型验证/五项产物构建通过；这不代替真实宿主的完整学习验收。
