# forge · 锻造

**先自己想，再看答案。** · Think first. Then look.

forge 是一个供 AI Agent 调用的中文学习技能。安装后，在 Agent 会话中用 `$forge` 加上你的学习目标或材料即可开始。Agent 按技能规则核对材料、组织学习、提出问题、复核真实作答，并按需生成交互学习页、可编辑思维导图和学习档案。已登记的主题可在当前工作区查找，选定后读回目标、暂停位置、原答和缺口，再接着学习。

你负责提出目标、解释、作答和决定是否继续；Agent 负责调用随包工具、保存记录和交付产物。日常使用不要求你手动创建知识模型、逐条运行 CLI 或管理档案字段。

> 项目采用 MIT 许可证，GitHub 仓库为 [ChengYueCode/Fogre](https://github.com/ChengYueCode/Fogre)。GitHub 技能安装不要求 Forge 发布到 npm。完整产物与存档能力需要 Agent 具备文件读写、命令执行权限，以及 Node.js ≥20 的运行环境。只有对话能力的 Agent 无法完成本地工具交付；不同宿主的发现和调用方式以其实际支持为准。

## 适合用来做什么

| 你的目标 | Forge 的处理方式 |
| --- | --- |
| 学一个新主题 | 收敛可观察成果，轻量诊断并等你回答，按实际缺口组织有限路线 |
| 整理已有资料 | 核对材料，组织概念、关系、例子和练习，生成学习页与导图 |
| 检查自己的解释 | 用针对具体缺口的提问检查推理，一次一个主要问题，等待真实回答 |
| 检查已经提交的答案 | Agent 读取原答与核对依据，保存对应反馈，保留原答和后续修正 |
| 安排本次复习 | 根据指定主题的到期项、前置缺口与时间预算说明选择和暂缓理由 |
| 查找已有学习 | 从本地索引查看已登记主题，实时读取目标、位置与待复习状态 |
| 继续上次学习 | 选定主题或提供目录，读回原答、反馈和缺口，续接同一适用轮次 |
| 换会话或交接档案 | 核对可读目录或导出文件，保留历史、说明冲突与内容变化 |
| 回看理解变化 | 按概念汇总自己的解释、总结、误解、修正、反馈与自创问题 |

这些能力共用一条学习循环：**明确目标 → 看清关系 → 自己解释或应用 → 根据缺口修补 → 留下记录与检索问题 → 以后再次提取**。

Forge 优先服务个人学习者；你也可以只整理资料，不进行现场提问或掌握评估。学习页与导图服务理解、练习和复习，生成它们不等于已经掌握。

## 安装技能

GitHub 是技能的分发来源；`skills` 是安装工具，Forge 本身不需要先发布成 npm 包。安装后，在支持技能调用的 Agent 会话中直接使用 `$forge`。

> 下列命令安装 GitHub 仓库中的完整技能目录。环境与验证范围见支持说明；安装成功与宿主实际调用分别核对。

### 方式一：用 skills 从 GitHub 安装

推荐只安装主技能：

```sh
npx skills@latest add ChengYueCode/Fogre --skill forge
```

按安装器提示选择目标 Agent 和安装范围。先查看可安装技能：

```sh
npx skills@latest add ChengYueCode/Fogre --list
```

默认安装到当前项目；跨项目使用可以增加 `--global`。例如，明确安装到 Codex 的用户级范围：

```sh
npx skills@latest add ChengYueCode/Fogre --skill forge --agent codex --global
```

仓库当前的主技能路径是 `skill/forge/`。也可直接指定该目录：

```sh
npx skills@latest add https://github.com/ChengYueCode/Fogre/tree/main/skill/forge --skill forge
```

命令和参数依据 [Skills 官方说明](https://github.com/vercel-labs/skills#install-a-skill)。运行 `npx` 需要 Node.js/npm 与网络；Forge 随包工具要求 Node.js ≥20。安装器不会因此配置模型或赋予 Agent 工具权限。

### 方式二：让你的 AI 帮你安装

把下面提示词交给有网络和文件工具的 Agent，使用真实仓库链接：

```text
请从 https://github.com/ChengYueCode/Fogre 为当前 Agent 安装 Forge 学习技能。

先阅读仓库 README，确认主技能 skill/forge/SKILL.md 的 name 是 forge。
只安装主技能，不需要安装全部单项入口。
优先使用 npx skills@latest add 的方式；根据当前宿主选择正确的安装范围和位置。
如果需要选择项目级还是用户级，先说明选择，并按我的偏好处理。
若该方式不可用，使用当前宿主支持的 GitHub 技能安装方式，
从 skill/forge 安装完整目录，包含 references、scripts 和 assets，不能只复制 SKILL.md。

已有同名技能时先检查版本与位置，不直接覆盖或创建重复副本。
安装后检查关键文件和 Node.js 环境，说明宿主如何加载或刷新技能。
无法下载、写入或确认宿主发现时，请说明实际阻塞，不要宣称安装完成。
```

这种提示词委托 AI 执行安装，不绕过宿主权限，也不保证所有 Agent 都有安装工具。完整安装后，再按宿主要求加载或刷新并确认可以调用 `forge`。

### 当前源码的本地试装

在源码根目录可先列出真实技能目录中的入口并隔离试装：

```sh
npx skills@latest add ./skill --list
npx skills@latest add ./skill/forge --skill forge
```

主技能与五个单项入口均在 `skill/` 下。请不要对包含内部 `.scratch/` 历史副本的整个工作区直接安装：根目录递归发现可能选中旧技能。

从干净的发布目录发现六个入口，以及通过 Skills 安装完整主技能的本地路径已验证；GitHub 发布后的下载、更新与真实宿主调用仍需分别核对。项目自带安装器和可选全局 CLI 的使用见[安装指南](../docs/installation.md)。

## 直接在 Agent 中开始

场景：你能读简单代码，希望理解二分查找为什么正确。安装并加载后，在会话中输入：

```text
$forge 带我学习二分查找，目标是独立解释循环不变式，并判断边界是否正确。
```

场景：你已有笔记或文章，希望先得到学习产物。可以直接带材料：

```text
$forge 把我提供的资料整理成交互学习页和可编辑思维导图，保留我的疑问。
```

不需要先手工运行示例模型、构建页面或启动服务。Agent 根据这次请求选择能力，需要产物与持久档案时调用随包工具；信息不足或权限受限时说明具体缺项，不虚报交付。

场景：还没有自己的材料，希望先体验学习流程。可用随包概率示例：

```text
$forge 用技能自带的 probability.json 教学示例，带我体验一次学习。
请把产物和记录放在 learning/probability，需要学习页时给我可访问的位置。
```

该模型包含教学假设，不是你的历史作答或医疗判断依据。已有同名学习目录时应先核对记录，避免把示例当成重新初始化的理由。

下列请求可选增加时间预算、相关基础、讲解偏好或学习目录；它们不是每次调用都必须填写的表单。材料应作为会话附件提供，或放在 Agent 有权读取的位置。

## 使用实例

以下场景展示实际支持的请求方式，不是真人学习成果。目标、材料和真实回答由你提供；完整产物与存档需要相应工具权限，保存情况以实际读回为准。示例目录相对当前会话工作目录解析。

### 1. 学新主题：看过代码，但说不清为什么正确

**场景**：你能读简单代码，学过二分查找，却容易混淆左右边界，希望这次能解释正确性，而不只是背模板。

```text
$forge 带我学习二分查找，目标是独立解释循环不变式，并判断边界是否正确。
我能读简单代码，但容易混淆左右边界。这次有 20 分钟。
请把产物和记录放在 learning/binary-search。
```

**预期处理**：核对相关基础与材料，提出一个诊断问题并等你回答，再按真实缺口校准有限路线。需要时生成学习页和可编辑导图；保存目标、原答、协助、修正与暂停位置，并登记主题目录。预算不足的部分明确暂缓，不把路线已提交说成已掌握。

### 2. 只整理材料：已有笔记，希望得到可探索的学习产物

**场景**：你有课程笔记或文章，想先看清概念关系，暂时不接受现场提问。

```text
$forge 只整理我提供的二分查找笔记，生成学习页和可编辑思维导图。
保留我的疑问，标明材料依据与尚未核对的部分。
请放在 learning/binary-search，不要现场提问或评估掌握度。
```

**预期处理**：核对可读材料并交付产物，不强制画像或诊断。学习页保留可复用的练习与参考，初始掌握度保持未知；已有目录先读回，重建保留有效记录，不重新初始化。同一请求可用独立入口 `$forge-organize`。

### 3. 检查解释：觉得懂了，想让问题暴露漏洞

**场景**：你能给出解释，但不确定它是否遗漏条件，希望先自己推理。

```text
$forge 只用提问检查我的解释：
“二分查找每次把范围缩小一半，所以任何有序数据都能直接套用同一种边界写法。”
先检查最关键的一个缺口。
```

**预期处理**：围绕一个缺口提一个主要问题，然后等待你的真实回答，不提前代答或评分。你可以请求改为讲解或停止。没有档案时在会话中讨论，不宣称已持久保存。同一请求可用 `$forge-question`。

### 4. 请求帮助：卡住了，需要换讲法或完整示范

**场景**：正在学习一项边界判断，你回答“不知道”，希望得到足够起步的帮助。

```text
这个地方没理解，请换一种讲法，给我一个完整示范，再让我自己试一个变式。
```

**预期处理**：沿用当前目标与任务，针对缺口提供解释、起步帮助或示范，保存真实协助来源，再等待你的尝试。示范后的作答按实际帮助情况记录，不算成无协助的独立回忆证据。学习用途的假设案例与真实业务决定分别说明。

### 5. 复核作答：已经提交，希望知道具体哪里有问题

**场景**：你已在会话或自动存档学习页完成一批练习，想集中获得反馈。

```text
$forge 检查 learning/binary-search 里本轮已经提交的作答。
说明正确部分、具体误解、核对依据和修补建议，保存反馈，并更新学习页供我查看。
```

**预期处理**：固定本轮复核范围，核对原答、题目、参考与判定标准，逐项保存并读回反馈。原答保留，修正另记；缺依据、内容变化或无法判断的项明确待处理。无轮次历史需先选择具体作答范围。同一请求可用 `$forge-review`。

### 6. 安排复习：时间有限，先补最影响当前目标的缺口

**场景**：今天只有 15 分钟，希望继续二分查找，不想重复刷所有题。

```text
$forge 根据 learning/binary-search 的记录安排 15 分钟复习。
优先处理左右边界相关的缺口，说明选中理由和暂缓项。
```

**预期处理**：根据这个主题的必要前置、主动重点、重复错误与真实到期项安排，说明预算内的选择与暂缓理由。没有到期记录就如实说明；未选中不等于完成或遗忘。这不是自动跨主题复习总计划。同一请求可用 `$forge-review-plan`。

### 7. 暂停：时间到了，希望保留下次的起点

**场景**：当前任务还没答完，你需要结束这次交流。

```text
今天先停在这里，请保存当前进度和未完成任务，说明下次从哪里继续。
```

**预期处理**：停止展开新任务，说明实际完成范围、未解决缺口、保存方式和档案位置，保留原轮次与暂停位置。未作答任务仍是未作答，不把“先停下”改写成路线完成。

### 8. 新会话续学：忘记目录名称，想找回已有主题

**场景**：仍在原工作区，之前学习的主题已经登记，但你不记得目录名称。

```text
$forge 我想继续之前的学习。先查看当前工作区已登记的主题，
告诉我各自停在哪里、还有哪些缺口和待复习内容，让我选一个继续。
```

**预期处理**：读取本地索引并实时读回主题档案。选定后恢复目标、位置、原答、协助、画像和材料变化，再续接适用的原轮次。索引缺失时询问已有档案位置，不把空索引解释为从未学习；缺文件的主题明确报错，不建立空档案。

如果主题或目录已明确，可以直接说：

```text
$forge 继续 learning/binary-search 的学习。
先读回上次目标、暂停位置、原答、反馈和缺口，再接着学。
```

### 9. 换工作区：带着档案继续，而不是依靠旧聊天

**场景**：你将学习目录和索引整体复制到了新工作区的 `my-learning/`，需要找回其中的主题。

```text
$forge 我的学习索引是 my-learning/learning-index.json，相关主题目录也已一起迁移。
请查看这个索引，找到 binary-search 主题，核对材料或目标是否变化后继续。
```

**预期处理**：使用指定索引及相对它定位的档案，读回旧记录与当前差异。文件不可读或指针失效时先核对位置；索引不自带题目与答案，需要对应主题目录。不会自动搜索所有设备或同步账号。

### 10. 独立页面交接：浏览器里做过题，会话还没收到记录

**场景**：你直接双击 HTML 做了练习，新增答案保存在浏览器缓存，现已从页面导出档案。

```text
$forge 我从学习页导出了 backup/binary-search-state.json。
请核对它是否属于 learning/binary-search，导入后复核真实作答，并更新学习页。
遇到冲突请保留并说明。
```

**预期处理**：核对模型、内容版本与来源，合并合法记录，处理冲突，复核并重建可信新版页面。导出不等于导入，导入不等于复核；没有收到可读导出文件时不能声称读取了浏览器答案。

### 11. 回看理解变化：从原来的误区里形成复习线索

**场景**：已学过几轮，希望看到自己对左右边界的解释如何变化，而不是再生成一篇通用总结。

```text
$forge 汇总 learning/binary-search 中我的误区和理解变化。
按概念展示原答、修正、反馈和自创问题；没有记录的部分不要补写。
```

**预期处理**：只聚合已有档案，区分当前内容、历史答案和缺失记录，不新建事实或增加掌握证据。同一请求可用 `$forge-insights`。

### 12. 纠正讲解：发现 AI 的说明与材料原文冲突

**场景**：你核对原文后发现讲解或参考答案可能有错，需要连同受影响的练习与记录一起检查。

```text
你对终止条件的讲解与我提供的原文不一致。
请回读原文，核对受影响的解释、练习、参考和记录，保存纠错依据并保留我的原答。
```

**预期处理**：先回读相关原文，再说明准确解释和依据，核对六类影响并保存纠错历史。受误导原答保留，后续尝试另行关联；纠错本身不证明你已掌握。

完整示例与五个独立入口的场景对照见[场景与使用示例](../skill/forge/references/usage-examples.md)。

## 一次学习中你和 Agent 分别做什么

| 环节 | 你做什么 | Agent 做什么 |
| --- | --- | --- |
| 开始 | 提供目标或材料，可补充基础与预算 | 判定完整学习或单项能力，读取对应规则与材料 |
| 理解与练习 | 自己解释、作答，指出不懂的地方或请求帮助 | 等待真实回答，按缺口讲解、提问或示范 |
| 产物与保存 | 使用交付的页面和导图，补充自己的理解 | 准备模型、构建产物、按规则保存并读回记录 |
| 反馈 | 提交真实答案，必要时请求复核 | 核对原答与依据，分别保存反馈和修正 |
| 收尾 | 决定继续、暂停或调整目标 | 说明实际完成范围、未解决缺口与已保存位置 |
| 下次 | 指定主题、档案目录或已有索引，选择继续内容 | 查找已登记主题，读回适用信息与变化，续接学习 |

**导师就是当前会话中按 Forge 规则工作的 Agent。** 随包脚本是 Agent 使用的辅助工具，本地服务用于学习页自动存档，不是另一个导师。

## 学习页与学习档案

学习页是 Agent 按需交付的学习产物，不是调用技能的前置步骤。你可以在会话中学习，也可以打开页面探索概念关系、查看解释和例子、作答、补充笔记，以及回看“洞见与速查”。完整旅程涉及的学习记录由 Agent 按实际活动保存；纯单项讨论不必建立整套档案。

练习默认隐藏参考，提交非空原答后显示；主动请求帮助时保留协助来源。比较对照、分步推演和参数实验只有在模型配置对应组件时出现。

### 保存在哪里

Agent 将主题产物放在你选择的学习目录，并在交付时说明位置与保存方式。未指定目录且位置影响写入时，需先明确；不要把个人档案放在技能安装目录。

| 文件 | 内容 |
| --- | --- |
| `index.html` | 交互学习页 |
| `model.json` | 概念、关系、问题、参考、来源与局限 |
| `state.json` | 轮次、原答、协助、笔记、修正、反馈与复习记录 |
| `map.excalidraw` | 可编辑导图 |
| `map.svg` | 使用相应构建选项时生成的静态预览 |
| `quality.json` | 单独填写和写入的作者内容质检记录，不由每次构建自动产生 |

### 下次如何找到学习记录

Agent 在新建或接收标准学习目录后登记主题。默认索引是当前工作区的 `learning/learning-index.json`，它只保存目录指针与身份；原答、修正和掌握依据继续保存在主题的 `state.json`。查看索引时实时读取各主题的目标、位置和到期状态，避免拿旧摘要代替当前记录。

在原工作区，你可以说“查看我已登记的主题，让我选一个继续”；知道目录时可直接指定目录。旧目录需要先登记才能被索引找到；换工作区时提供索引位置和对应主题目录。移除索引指针会保留学习文件。档案更新时间不等于实际学习时间，缺失记录保持未知。

索引提供本地查找，不自动扫描所有目录、合并不同主题画像或同步设备。独立 HTML 的新增答案仍需导出和导入后，会话才能读到。具体规则见[学习档案入口](../skill/forge/references/learning-library.md)。

### 在页面作答后怎样继续

- **本地服务模式**：Agent 按需启动服务并交付地址；服务运行时页面直接写回学习目录。提交保存后，告诉 Agent 复核同一主题即可。关闭服务后已写入档案保留；下次可请求 Agent 重新打开。
- **独立 HTML 模式**：页面新增记录只在当前浏览器缓存。需从页面导出档案，再把文件交给 Agent 核对、导入与复核；缓存未导出前，Agent 不能声称已读取答案。
- **反馈或内容更新后**：Agent 重建页面，交付新版位置；重新打开或刷新读取更新后的反馈。

场景：你直接双击 HTML 做了题，已导出浏览器记录，希望交给 Agent 复核。可以这样请求：

```text
$forge 我从学习页导出了 backup/binary-search-state.json。
请核对它是否属于 learning/binary-search，导入后复核真实作答，并更新学习页。
遇到冲突请保留并说明。
```

网页不自行调用模型批改，也不提供内置 AI 聊天。导出不等于导入，导入不等于复核；保存失败必须说明实际保存范围。

导图编辑可在 Excalidraw 打开 `map.excalidraw`，将导出文件交回主题目录，请 Agent 重建并保留有效编辑。图形文字修改不自动改变知识模型语义。

## 单项技能入口

仅安装主技能即可用 `$forge` 选择上述单项能力。希望在宿主中直接按能力调用时，可选安装独立入口：

| 入口 | 适用场景 |
| --- | --- |
| `$forge-organize` | 只整理资料，生成学习产物 |
| `$forge-question` | 只用提问检查解释或推理 |
| `$forge-review` | 复核已经提交的真实作答 |
| `$forge-review-plan` | 在预算内安排复习 |
| `$forge-insights` | 汇总已有误区和理解变化 |

选择安装一个入口：

```powershell
npx skills@latest add ChengYueCode/Fogre --skill forge-question
```

这些入口由主技能的唯一规则源生成。宿主实际发现后才能使用对应调用名；无需为一次完整学习安装全部入口。

## 常见问题

**必须安装全局 CLI、手动启动服务才能用吗？**

不必须。完整技能目录包含随包工具，Agent 可直接使用安装目录中的脚本；本地服务只在需要页面自动存档时按需启动。全局 CLI 是可选操作方式，不是日常调用技能的入口。

**我需要自己写 JSON 模型和维护档案吗？**

常规使用不需要。你提供目标、材料和真实回答，Agent 按规则准备模型、保存与读回。权限或环境不足时需要解决具体阻塞，不能把未执行的工具步骤当成已完成。

**能装到任何 Agent 里吗？**

核心以 `SKILL.md` 与随包资源交付。宿主需要支持相应技能加载；完整功能还需要文件与命令工具。当前没有对所有宿主和操作系统的兼容保证。

**只想提问检查，也要生成学习页吗？**

不需要。单项提问可以直接在会话中进行；没有档案的讨论不宣称已经持久保存。

**换会话后能记住我吗？**

恢复依赖可读学习档案，不依赖旧聊天。已登记主题可在原工作区查找；你可以说“查看已登记主题，让我选一个继续”，Agent 再读回目标、位置与原答。换工作区时提供索引位置及对应目录，旧目录先登记；独立浏览器的缓存仍需导出和导入。日常无需手动运行索引命令。

**是否完全离线？**

学习文件可以保存在本地，AI 会话的数据处理仍由宿主决定。联网模型、来源核对或远程编辑器可能依赖网络；本地存档不等于整个过程离线。

## 能力边界

- 页面生成、阅读、展开节点、写完笔记与自评不会自动提高掌握度；判断需要可核对的真实表现。
- 复习使用透明、确定性的简单规则，不是 FSRS，不保证长期记忆或固定时间精通。
- AI 讲解与反馈可能出错，需要保留来源、协助、纠错依据和未核对范围。
- 单项讨论没有档案时不能宣称已保存、更新掌握度或安排了持久化复习。
- 本地索引支持已登记主题的查找与续学读回；跨主题复习总计划、云同步和网页内 AI 对话尚未实现，本地服务不在后台自行持续教学。
- 可编辑导图交付与实时 Excalidraw MCP 展示是不同能力；后者依赖宿主提供相应工具。
- 自动化测试、浏览器检查与合成代理试用验证对应功能路径，不证明真人长期学习效果。
