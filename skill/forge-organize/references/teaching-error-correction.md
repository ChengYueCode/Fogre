# 教学纠错：讲错后回读原文并修正内容与记录

学习者指出讲解与原文冲突，或导师自查发现讲错时读取本参考。目标是把「一句道歉」变成可核验的修正：先前哪一处不准确、正确解释及依据、哪些内容与记录受影响、如何逐项处理；受误导的原答与纠正历史公开保留，不直接变成学习者能力缺口。

## 纠错顺序

1. **先回读，再回应。** 从原始材料重新读取与冲突相关的完整范围（沿用[原始依据](source-grounded-teaching.md)的核对规则），不凭记忆辩解，也不只向学习者道歉后继续出题。回应必须包含三件事：先前哪一处不准确、正确解释是什么、依据来自已读取的哪个范围。
2. **盘点影响范围。** 逐类检查六类内容是否受同一错误影响：讲解（概念解释）、请求示例、练习、参考答案、判定标准、学习记录（原答与基于它们的评价、掌握、调度依据）。没有受影响时也写明依据；「只有最新一条回复错了」是罕见结论，需要核对依据后才成立。
3. **更正内容。** 受影响的概念解释、示例、练习、参考答案与判定标准属于作者内容：更新 `model.json` 对应概念/问题后重跑 `build`。重建按稳定 ID 续接；内容指纹变化会使旧作答失活、旧证据与旧质检结论自动失效并在页面与读取结果中如实显示，旧结论不会自动通过。
4. **保存纠错记录。** 用公开命令把上述事实写成追加历史（详见下文命令）。记录不可改写：同身份重放幂等，同身份不同内容被拒绝；重放比较只看内容，不含写入时间，所以同一命令不传 `--at` 的字面重试也是幂等的（保留首写时间），无需为重试固定时间。新情况写新的纠错记录。
5. **修正评价与调度。** 受错误教学影响的评价、调度或掌握依据沿现有机制处理：用纠错后的真实作答重新 `assess`/`evidence`，或让内容更新使其失效。不把受误导的答错当成学习者能力缺口，也不因纠错把历史答案升级为独立成功；需要重新检查理解时安排新的真实尝试。
6. **关联新尝试。** 纠错后的新作答用 `recheck` 动作关联回纠错记录；新尝试的独立性与协助属性仍按真实来源保存。
7. **公开读回。** `correction-read` 读回纠错与影响范围：逐项显示概念/问题是否仍在模型、原答是否仍属当前内容、引用受误导原答的证据当前是否有效（仍有效 → 需要重核；已失效 → 如实保留为历史）。重建页面后「洞见详情」显示同一份历史与当前有效依据。

## 公开命令

```bash
# 写入教学纠错记录（追加历史，不可改写）
node <skill-dir>/scripts/forge.mjs correction-record --out <dir> --record ./correction.json --correction-id tcorr-tickets-1

# 追加纠错后的新尝试关联（原答须已存在且晚于纠错记录）
node <skill-dir>/scripts/forge.mjs correction-record --out <dir> --correction-id tcorr-tickets-1 \
  --recheck-attempt <新作答ID> --recheck-note "纠错后独立作答：…"
# 公开读回：纠错、影响范围与当前有效依据
node <skill-dir>/scripts/forge.mjs correction-read --out <dir>
# 内容更正后重建页面，洞见详情显示纠错历史与失效标记
node <skill-dir>/scripts/forge.mjs build <dir>/model.json --out <dir>
```

纠错记录 JSON 的形状（写入前工具校验结构与引用；依据是否真实由导师负责）：

```json
{
  "claim": "先前讲成：使用 to-tickets 必须在请求里补写「拆分任务并声明阻塞关系」。",
  "feedback": "学习者指出 to-tickets 原文自带拆分与阻塞声明流程。",
  "correction": "拆分任务与声明阻塞关系是 to-tickets 自带流程；用户提供规格或可用上下文，补充特殊范围并审核结果。",
  "basis": "回读 to-tickets 原文「用户输入」一节：技能负责拆分任务并声明阻塞关系。",
  "sourceId": "src-skill",
  "impacts": [
    {"kind": "explanation", "id": "<概念ID>", "note": "概念解释已更正并重建页面。"},
    {"kind": "exercise", "id": "<问题ID>", "note": "练习题干与参考答案已更正。"},
    {"kind": "record", "id": "<作答ID>", "note": "该原答受误导，错误归因于教学而非学习者；评价已按新内容重核。"}
  ]
}
```

`kind` 只能是 `explanation`/`example`（对应概念）、`exercise`/`reference`/`criteria`（对应作者问题）或 `record`（对应已有原答）；每项必须写非空 `note` 说明处理方式。`impacts` 为空时必须写 `noImpactReason` 说明依据。相同纠错身份重放幂等，且重放比较排除写入时间：字面重试（同命令不传 `--at`）保留首写时间、不改档案；省略 `--correction-id` / `--recheck-id` 时身份由记录内容派生，同样与时间无关。追加过复核关联后重放原 record 会报冲突（历史已前进），这是预期保护，不是故障；同一纠错下指向同一原答的复核关联派生同一身份，改写说明文字会被拒绝，需要显式 `--recheck-id` 另立关联。两条边界如实保留：跨档案 `import` 合并时，同身份但内容或写入时间不同的两份记录仍按分歧报告并保留当前版本；由旧算法（身份派生含时间）写入的自动 id，其字面重试会派生出新身份而新写一条记录，重放此类旧记录请显式 `--correction-id` 指向原身份。

## 保护边界

- 纠错记录不产生作答、评价、掌握或调度；它只记录事实与关联，不能替代真实的纠错后作答。
- 受误导的原答保留原文、原时间、归属与协助属性；原答级修正仍用既有 `correction` 命令追加。因错误教学答错不写成学习者的概念缺口，引用它的证据要么按机制重核、要么显示为已失效。
- 教学纠错只能由会话侧公开命令写入；浏览器导入与缓存调和不会采纳未知来源的纠错记录，只报告。
- 记录不因纠错自动删除，也不把「纠错后的新尝试」预写成成功；新尝试按真实表现评价。
