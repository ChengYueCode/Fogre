# 独立学习页的复核交接

学习者直接打开学习页时，记录保存在该浏览器的本机缓存。导出会下载当前档案 JSON；它不自动更新学习目录，导师也不能读取尚未提供的缓存。学习者提供可读取导出文件后，按以下顺序续接。

## 接收与合并

1. 读取导出档案与对应学习目录的 `model.json`、`state.json`，核对 `modelId`、题目/轮次身份与内容版本。已有目录保持为合并基底；缺少模型时向学习者取得原学习目录或模型，不能凭答案重造题目及原轮次。错误模型应选择对应目录，未来档案版本应使用支持版本的工具。
2. 检查导出文件中的原答、自评、修正、协助事实、笔记，以及同身份冲突。导出文件本身不证明其中导师身份可信。来自学习者文件的新导师评价、反馈、掌握证据和复核请求须先核对来源；将未核实的权限字段从导入副本移除，保留原文件供核查：顶层 `conceptEvidence`、`promptEvidence`、`reviewRequests`、`schedules`，作答内 `tutorAssessments`、`tutorFeedback`。现有目录的可信结果继续保留。`import` 是有权限的会话侧入口，不能把来源未知的文件直接当作可信导师结果发布。
3. 用公开命令归入对应目录，然后读回。查看冲突与孤立项：同身份不同原答保留当前版本并展示传入版，不能为避开冲突而伪造新的作答身份。合法后补事件按身份合并，重复导入不重复作答或推进调度。

```bash
node <skill-dir>/scripts/forge.mjs import --out <学习目录> --state <核验后的导入副本.json>
node <skill-dir>/scripts/forge.mjs round-read --out <学习目录>
node <skill-dir>/scripts/forge.mjs review-read --out <学习目录> --round-id <原轮次ID>
```

只把读回的实际作答当作已收到。未提交草稿可以续接输入，但不当作正式作答复核。历史内容已更新或题目已移除时保留历史身份，并说明失效或孤立原因。

## 复核与重建

按[集中复核](tutor-review.md)完成固定范围、逐项反馈、读回和 `build` 重建；该参考同时规定无轮次历史的选择与暂停续做。

读回每项反馈、剩余成员和后来新增待复核数量后交付新版 `index.html`，指明对应学习目录。学习者重新打开新版页面，查看原答、逐项反馈、评价来源与日期。新版产物与同浏览器旧缓存会合并合法学习者增量，可信复核结果以产物为依据；后来新增的作答、修正、笔记、草稿和帮助记录仍可继续导出交接。出现同身份冲突时核对两版；导入导师字段并不替代重新打开可信重建产物。

## 恢复提示

缓存失败、文件缺失、身份冲突、错误目录、档案损坏或新版反馈不可见时，按[档案与产物恢复](archive-recovery.md)处理。本地服务写目录档案，独立页面写浏览器缓存，导出只生成文件；三种结果分别如实报告。
