# 了解学习者与有限开场

用于现场学新主题，或已有画像需要复用、纠正时。整理材料和 artifact-only 继续直接交付；画像与现场诊断只服务于需要它们的教学，不是生成产物的门槛。

## 先复用，再补问

1. 读当前对话和学习者授权的可读学习目录：`round-read --out <dir>`；需要历史画像时对返回的 rounds 逐个指定 `--round-id` 读回。未指定目录且需要找回已有学习时按[学习档案入口](learning-library.md)查已登记主题；画像仍以选定档案为依据，不跨主题自动合并。确认信息仍适用，简短复述，给纠正机会。
2. 对角色与实际任务、相关基础、讲解偏好，只询问会改变教学台阶的缺项。问题可合为自然语言一句，学习者可一次回答多个方面；已有信息不用重问完整问卷。会用 GitHub 只说明会用 GitHub；代码、命令和开发经验分别核对。单次错误只形成当前内容缺口，不改变整体能力标签。
3. 学习者跳过时保持未知，说明暂行教法，例如“先按无需开发经验的具体操作演示，术语随用途解释；你随时可以让我加深或加快”。仍可继续收敛目标。学习者的角色和偏好不等于掌握证据。

目标写成能观察的行为，如“给一份已有规格选择技能，写出最小调用请求，并检查输出是否满足规格”。“了解整个仓库”可先收敛为一个用途，不能暗中承诺精通整个仓库。

画像复述和诊断解释须指向学习者真实原话。学习者请求额外交付说明，不代表他认为这些要求是技能必须依赖的提示；只有实际回答体现了某个误解，才将它报告为该项缺口。

## 展示初步范围，等待真实诊断

说明本轮是一段可暂停的学习过程；单元是一个有成果和转段标准的内容块；互动是学习者的一次实际回应，三者数量不同。展示有限单元、必要前置、预计时间、成果和检查标准。诊断前称“初步范围”，真实回答后才称“校准路线”；诊断只检验目标相关内容，提问后等待，工具调用或导师示范不会代替学习者原答。

预算未指定时，先安排首个目标及其必要前置，其余明确留待续接。时间估计采用工具现有逐任务估算相加，诊断另列；复杂前置可能使这个小单元较长，导师须如实说明，必要时和学习者缩小目标。固定四单元、固定问答次数不是所有主题的模板。估计不是承诺，也不是用户指定上限。

用户时间上限保存为轮次 budgetMinutes；可选互动上限保存为 opening.interactionLimit。互动起点、记录与预算执行见 [visible-progress-and-budget.md](visible-progress-and-budget.md)。结束条件是目标已有足够表现证据、用户预算用尽或用户主动暂停/结束。路线任务已提交只表示有待核对的原答，不能据此宣布掌握。

有限单元必须支持这轮实际目标：若小单元前缀只能做到“写出请求”，就分别说明本轮小目标与尚未开展的“核验交付”，或和学习者约定调整目标范围。不能把暂缓单元的成果写成已可达成的本轮结束标准。诊断或任务的预计分钟不表示实际已经投入这些时间；实际时间未知时保持未知。

## 保存与读回

画像和范围归属当前轮次 `opening`；旧轮次没有 opening 时读作 null（未知），不补造历史。导师把学习者自然语言整理成下面的 JSON；工具本身不解析自然语言。`sourceNote` 写真实依据，缺项用 null，缺项或主动跳过时写 temporaryApproach。

```json
{
  "learner": {
    "role": "负责运营与工具选择",
    "task": "用已有规格推进任务开发",
    "background": "会用 GitHub 查看资料，没有开发经验",
    "preference": "完整演示后边做边学",
    "sourceNote": "学习者本轮自然语言陈述；已简短复述可纠正",
    "skipped": false,
    "temporaryApproach": null
  },
  "interactionLimit": null
}
```

```bash
node <skill-dir>/scripts/forge.mjs round --out <dir> --action create --entry learn-new-topic --round-id <ID> --goal <可观察成果> --concept <概念ID> --opening <opening.json> [--minutes <用户上限>]
node <skill-dir>/scripts/forge.mjs round-read --out <dir>
node <skill-dir>/scripts/forge.mjs round --out <dir> --action update --opening <纠正后的opening.json>
```

工具从现有任务自动保存 preliminary，诊断确认后保存 calibrated；导师不能通过 opening 输入自行声明已完成诊断。画像修改保留旧画像历史，省略 learner 保留画像，省略 interactionLimit 保留上限，null 清除上限。路线调整保留初步范围，校准范围读回标明目标/内容变动后的失效。已有轮次复用相同身份，已有画像纠正后显式保存；仅在需要另开主题时建立新轮次。

若新主题诊断后才首次保存画像，preliminary 为 null（诊断前范围未知），不回填。预算不足时预计预算内用时为 0，表示当前没有可开始单元；读估计依据里的首个必要单元预计时间，缩小目标或增加预算后再开始。

HTTP `/api/round` 接受相同 opening 参数，沿用档案锁、冲突及版本检查。build 后页面“本轮”读回开场；服务直接保存，独立页缓存必须导出后才交给会话，详见学习轮次和交接参考。

## 开发经验有限时的完整演示

案例：已有规格，希望让 AI 开发其中一个任务。用途是把意图交给合适技能并检查结果，学习点是调用与产物审核，而非编程能力诊断。

- 用户说：“使用 implement 技能，开发这份规格中的 02 任务。”技能是一份 AI 工作说明；规格描述要得到的行为；任务是有边界的一个工作切片。
- AI 读取任务和它引用的规格，确认前置与验收条件，完成实现、适当验证与审查。具体职责先完整核对正在学习的真实技能原文；这是示范流程，不是所有技能的通用承诺。
- 得到修改文件、验证结果和剩余交付边界。文件改好了和已安装/已发布是不同状态，真实材料没确认的操作保持未核实。
- 学习者检查是否完成目标行为、测试是否覆盖实际用途、是否有遗漏、代码是否只是本地完成。再换一个已有任务，让学习者自己选技能、写请求并指出检查依据。

完整演示至少包含“用户怎么说、AI 做什么、得到什么、如何检查”，术语贴着用途解释。未知项可用明确标注的案例假设；达到示范所需的信息就返回学习路线，不能扩张成真实项目需求访谈。
