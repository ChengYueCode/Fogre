# 学习档案与产物的失败恢复

档案读写、浏览器缓存、导入或重建失败时读取。保留原输入与历史，按下表恢复；恢复动作不授权展开新教学或创建学习证据。

| 情况 | 续接动作 |
| --- | --- |
| 缓存写入失败 | 保持页面打开，先导出当前档案备份；只保留在内存的草稿另存为练习草稿，再重试缓存，不把内存内容当作已归档。 |
| 会话没收到可读文件 | 从页面导出并提供文件；截图或请求文本不作为档案。 |
| 同 `attemptId` 不同原答 | 保留当前记录并展示传入版本；不改写不可变事实，也不为避开冲突伪造新身份。 |
| 旧档 `schemaVersion: 1` | 首次写入前自动留逐字节 `state.v1.backup.json`；`restore --out <dir>` 核验后恢复。只读命令不改写磁盘。 |
| 错误目录或内容版本不一致 | 保留原导出文件，选择对应模型目录；对已更新题目只记录历史反馈或请求新的真实作答。 |
| 档案版本不支持或损坏 | 保留原缓存或文件；当前页面的新记录另行导出。可读但版本更高或属于其他模型的当前档案被拒绝并原样保留；当前档案截断或结构损坏时不阻塞恢复，`restore` 从同模型合法 v1 副本恢复，损坏字节另存 `state.corrupt.<时间戳>.json`。 |
| revision / 内容不一致（409） | 写操作携带 `revision` 与 `modelFingerprint`，不匹配返回可恢复冲突与当前状态；保留草稿和输入，载入新内容后再提交。 |
| 内容更新后旧证据或组件位置失效 | 保留历史作答并标 `stale`；`round --action update` 重新安排，取得新的真实作答；组件位置显式保存新位置，不静默沿用旧指纹。 |
| `.ember-lock` 冲突 | 返回可恢复冲突与当前状态；不要删除活动锁，遗留恢复锁需人工确认后清理。 |
| 服务关闭或重启 | 以 `<dir>/state.json` 为准，重新 `serve` 或重开 `index.html`，用 `round-read`、`due` 读回。 |
| 复核后仍看不到反馈 | 打开刚重建的 `index.html`；独立页面的"刷新复核结果"不能读取外部目录。 |
