# 模块交接约定：单项与嵌入模式

这份参考在某一能力模块将被单独使用（单项模式）或嵌入完整学习（嵌入模式）、需要交代输入、等待点、结果语义或记录约束时读取。它定义能力模块的交接约定，是会话层的说法约定，不是新增 JSON schema、CLI 参数或档案字段；各模块的规则正文与命令清单仍在各自的参考里，本文不复制它们。意图如何路由到模块见[能力路由](module-routing.md)。

## 两种模式

- **单项模式**：本次请求只做一件事（只提问、只复核、只复习、只汇总洞见、只交接），完成即结束。提问可基于真实解释直接开始；复核、复习安排与洞见汇总需要对应的可读档案，缺档案时说明必要输入，不虚构记录或展开完整旅程。
- **嵌入模式**：教学模块在真实教学过程中调用某一能力（例如轮次内用提问策略检查一个缺口），携带当前任务、预算与返回位置；能力完成后交回原任务，不重建轮次、不清空路线、不另建档案。

## 模块通用接口

每个能力模块在自己的参考里写清以下九项；本文是核对清单，模块正文缺哪项就补哪项，不在本文集中替模块回答：

1. 适用触发（哪些请求进入本模块）
2. 所需输入（缺哪项会无法开始）
3. 可选上下文（有则更好，无则保持未知）
4. 执行步骤
5. 等待点（何时必须停下等真实用户输入）
6. 完成 / 退出条件
7. 输出（给学习者看什么、给调用方交回什么）
8. 读写权限（读哪些目录、写哪些命令、明确不写什么）
9. 失败恢复与下一步

## 共同输入

进入模块时可用信息全部来自真实上下文，缺失值保持未知，不编造：

- 本次目标与范围；当前真实用户消息。
- 已核对材料（或明确「尚未核对」）。
- 可用预算（时间上限、互动上限；无则未知）。
- 已有任务 / 原答 / 协助信息（嵌入模式必须携带；单项模式可为空）。
- 返回到哪个任务（嵌入模式必填；单项模式为空表示结束即退出）。

## 结果语义

模块结束时用以下说明用语向调用方（或会话自身）交代状态。它们是交接词汇，不是要机械打印给学习者的状态码；对学习者仍说人话：

| 语义 | 含义 |
|---|---|
| `waiting-for-user` | 已提出问题或请求，正在等真实回应 |
| `completed` | 本次模块目标已达成，给了结论或产物 |
| `needs-context` | 缺必要输入，已说明缺什么 |
| `return-to-teaching` | 嵌入模式完成，交回原任务与返回位置 |
| `stopped` | 用户停止或预算耗尽，已保存可用状态并说明续接入口 |

无论哪种语义，都附：当前问题或结论、依据、未解决缺口、实际提供的协助、已保存与未保存范围、下一步。单项会话中「已保存范围」如实为零时，不得宣称归档。

## 记录约束

- **单项会话且无学习档案**：只报告当前讨论结果，不宣称归档、更新掌握或安排了持久化复习。
- **嵌入学习轮次**：读回真实 round / task / prompt / session 身份后再写入；策略不能重建轮次、清空路线或另建档案。
- **进度计数**：同一用户消息由编排层记录一个进度事件，子模块不重复计数；原答与进度事件的写入顺序沿用[进度预算](visible-progress-and-budget.md)的既有规则。
- **追问不是既有题目**：开放追问不自动成为已存在的题目。可保存为现有任务作答的内容必须确实回答该任务；需要新题时先准备模型与任务、读回有效身份再写入。不能把不同追问的答案塞进同一个 prompt，不能补造归属。
- **帮助与原答分开**：帮助记录与原答分别保存，原答不可变，修订另记；持久化失败时报告实际保存范围、保留真实文字用于恢复，不报告成功。

## 失败恢复

模块读取所需参考失败或源材料不可读时：报告缺口、限制结论范围、给出可行的下一步（例如「已基于你提供的文本完成检查，未核对原始材料」），不宣称核对完成。会话中断时单项模式无需恢复状态；嵌入模式沿用所属轮次的暂停与恢复合同。

## 调用方义务

编排层（SKILL.md 总入口或教学模块）在调用嵌入能力前说明：当前在哪个任务、为什么调用、预算多少、完成后回到哪里；调用后按返回的结果语义继续，不因能力返回而丢弃未完成的原任务。
