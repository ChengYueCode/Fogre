# 根据真实回应教学与控制案例

现场教学收到回应、学习者不理解、需要起步帮助、已有判断成功、案例逐渐离题或明确停止时读取。此参考用于导师会话决策；页面不调用模型，也不后台出题。开场沿用[画像](learner-aware-opening.md)，当前位置和收尾沿用[进度预算](visible-progress-and-budget.md)，材料规则先按[原始依据](source-grounded-teaching.md)核对。

真实回答暴露出具体缺口、且用提问检查比直接讲解更合适时，可按[苏格拉底提问](socratic-questioning.md)以嵌入模式调用：携带当前任务、预算与返回位置，问题澄清或需要讲解时按[模块交接约定](module-contract.md)交回本参考的推进规则。独立到来的单项请求（只提问、只复核等）先由[能力路由](module-routing.md)判定，不在这里展开成完整教学。

## 回复后先看什么

用 `round-read --out <dir>` 读目标、当前位置、待答任务、预算和收尾，用 `practice-plan --out <dir>` 读当前表现依据；需要原答/帮助时用 `insights --out <dir> --concept <id>`、`review-read --out <dir> --round-id <id>` 与合法可读 `state.json` 核对。旧档没有记录即未知，不从聊天认可或页面点击推断能力。每条真实回复以一个稳定事件 ID 写 `progress-event`，工具调用与导师消息不计数；无 progress 的旧轮次不要补造历史。达到硬上限先收尾，不继续加题。

| 真实回应与记录 | 下一步 |
|---|---|
| 认可回复、没有已提出而未回答的任务 | 按已说明的有限路线直接讲下一点或提出下一任务；若结束标准已有充分证据，基于证据收尾 |
| “好的/ok”、仍有待答任务 | 说明当前要由学习者做什么；可给第一步，不代填、不 submit、不评分 |
| “不知道” | 按需要给起步帮助、逐步提示或完整演示，然后等待学习者自己的尝试 |
| “没理解” | 先检查背景、术语与问题表达；换成具体说法或示范，改变教学方式，必要时询问卡在哪一步 |
| 真实正确答案 | 核对协助与完成标准，达标则转到更接近目标的请求编写、产物审核或新情境任务 |
| 真实错误答案 | 指出具体差异，解释缺的前置或机制；换情境核对这个缺口，不机械重复同类题 |
| 明确停止 | 立即停止讲解/追问/出题；只保存暂停点与未完成内容、给简短续接入口 |

“没有待答任务”由当时实际对话和任务记录共同判断；页面自动选中的路线任务不等于导师已把问题问出。认可也是实际互动，但不是表现证据。自然语言没有通用字符串判定器，导师须核对真实上下文，不能用 CLI 的非空答案检查代替此判断。

## 从演示到自己的尝试

对缺经验的学习者先解释术语的用途，再演示：**用户怎么说 → AI 做什么 → 得到什么产物 → 如何检查**。按已核对的材料演示，不伪造工具已执行或产物已存在。完整案例中的产物若只是示意，明确标为示意；教学请求不构成外部动作授权。

随后让学习者写自己的请求、审核一份示意产物或解释操作选择。帮助后的正确回答保留协助属性；获得当前、独立、导师核对的表现才按[递进规则](progressive-practice.md)转到变式或迁移。已有足够证据可跳过台阶；补同类题时说清具体缺口及需要什么新表现。选择判断只能证明相应判断，不能单独证明真实调用、开发或发布成功。目标要求独立应用时应准备有判定依据的应用题；现有题不足则补实际任务与标准，不能把解释题改名冒充应用。

完成标准先描述可观察行为，具体答案/评分细则在提交后或主动请求帮助时显示。原答案、自评、导师评价、掌握结论和调度仍各自保存；任务提交完成不等于学习目标达成。转段后用 `round --action update` 校准同一轮次，必要时保存 adjustment 的原因、已有证据适用范围、额外估计与明确跳过身份，并读回新的当前位置，不重新初始化轮次。

## 如实保存协助与原答

`hint` 是分步提示，`reference` 是参考答案/材料帮助，`tutor-feedback` 是导师反馈；新增 `starter` 是起步帮助，`demonstration` 是完整示范。一个练习可保留多个来源。演示或提示已给出，就在该题绑定的同一稳定练习身份保存来源，**帮助记录不 submit**。CLI/HTTP 和独立页均接受这些来源，旧档不会自动补写它们。

```bash
node <skill-dir>/scripts/forge.mjs practice --out <dir> --round-id <round> --task-id <task> --prompt <prompt> --session-id <session> --assistance demonstration
node <skill-dir>/scripts/forge.mjs practice --out <dir> --round-id <round> --task-id <task> --prompt <prompt> --session-id <session> --assistance starter
# 收到真实原答后，使用同一个 session，工具自动带入已保存协助。
node <skill-dir>/scripts/forge.mjs submit --out <dir> --round-id <round> --task-id <task> --prompt <prompt> --session-id <session> --attempt-id <stable-id> --answer <真实原答>
node <skill-dir>/scripts/forge.mjs insights --out <dir> --concept <concept>
node <skill-dir>/scripts/forge.mjs round-read --out <dir> --round-id <round>
```

给过演示后，不能换 session 隐去帮助再把同一答案称独立。新情境确实未获帮助才可独立记录；导师复核仍须检查是否用了参考或提示。`--assisted` 可保留已知有协助但具体来源未知的事实，不应拿它代替本次已知来源。停止前未提交的草稿用 `practice --draft` 及必要的 `--base-draft` 保存，不替学习者生成草稿。直接打开页面仅写浏览器缓存，导出并公开导入后才可宣称会话读到答案。

转到另一道应用题前，先通过公开轮次操作安排它并读回真实任务 ID，确认 `task.promptId` 就是实际提出的问题。当前路线没有对应任务时不能删去 `--round-id/--task-id` 绕过绑定；可按学习者明确的应用重点使用既有 `round --action review-plan --focus-prompt <prompt>`，核对前置和预算后再提出任务。不能把一份已有原答复制成第二次表现；保存或归属失败时保留真实回复、报告尚未归档的部分，先修复路线，再等待新的真实尝试。原答应保留实际回答的完整文字；同条消息中的导航可分为事件，但不得悄悄截去回答内容。无归属的历史/自由作答仍按原边界读取，不回填伪造轮次。

## 案例够用即返回路线

进入案例先说：“用这个案例练什么、只需要哪些信息、得到什么就返回路线”。例如练规格拆分只需一个可观察目标和两项范围约束；不为教学继续收集登录方式、推荐算法或完整运营规则。收到够用信息就用它示范/尝试，提醒当前单元与下一步。

把“为本例暂定”的规则标为假设，用户明确确认的真实规则另行标明；假设不变成项目决定或完整规格。追问新细节前确认它是否补当前学习缺口；否则暂存为以后项目讨论，回到任务。案例内容中出现“上线/开发”等词不构成执行授权。

用户想转真实项目时，收敛由用户明确决定的**模式、目标、范围与后续安排**，保留本轮记录并暂停教学。信息不明确则等待决定，不自动开发、发布、提交或写外部应用。本来已有明确授权的真实工作按其授权执行，不反复索取已有决定。

## 即时停止

看到明确停止先停止教学；不要先要求答完当前题。若 progress 仍可记本条真实回应，按一个事件保存；已被预算封闭或已收尾就不强行补事件。用 `round --out <dir> --action pause --round-id <id>` 保存同一身份；有 progress 时用 `close` 的 `learner-stop` 原因、缺口、续接点、保存说明与证据适用范围补充收尾。不把停止写成成功或目标达成。`pause` 保存暂停前的状态与当前任务，不接受备注参数；旧档无 progress 时只需 `pause`，续接说明在交付中如实列出，不宣称备注已写入档案，也不为了停止制造计数起点。

只读核对保存结果，说明剩余待答/有协助/待复核事实和续接入口即可；不追加练习，不定时唤醒导师。完整跨会话恢复由后续旅程合同核对，此处仅保存即时停止位置。
