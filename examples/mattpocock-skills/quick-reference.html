完整学习入口学习路线术语表练习

最常混淆的四件事

路由 ≠ 自动执行

ask-matt 提示入口；用户入口仍由用户明确发起。模型入口同时可由用户使用。

综合 ≠ 重新访谈

to-spec 综合已讨论内容，仍确认测试接口位置；to-tickets 另审核切片和阻塞边。

测试通过 ≠ 需求满足

code-review 分开检查规范与需求；一轴通过不能掩盖另一轴遗漏。

38 个入口的用途与边界

入口 / 身份当前场景预期产物关键边界
ask-matt
engineering / user		知道遇到了什么问题，却记不住该用哪个技能。技能选择建议与路线解释。它是用户调用的路由器，只提示下一入口，不替用户调用另一个用户入口。
setup-matt-pocock-skills
engineering / user		首次在一个仓库使用工程技能，尚未说明任务和领域文档放在哪里。任务追踪、标签映射、领域布局文档与已有指令文件中的导航。提示驱动而非确定脚本；已有 CLAUDE.md 时不另外创建 AGENTS.md；不得覆盖用户周边内容。
grill-with-docs
engineering / user		正在工作目录中讨论新功能，目标和术语仍含糊。澄清后的共同理解，以及领域词汇或适当的决策记录。原文入口是两个复用能力的组合；并不意味着每次都必须生成 ADR。
grill-me
productivity / user		只想推敲一个计划，当前没有需要维护的项目目录。共同理解的想法和已确认决定。不负责维护本地术语表；在工作目录中通常更适合 grill-with-docs。
grilling
productivity / model		一个决策包含多层依赖，容易在前置未定时乱问后续细节。逐轮澄清与已达成共同理解的决策树。依赖同轮未决问题的后续问题应留到下一轮；不代替用户回答。
domain-modeling
engineering / model		同一个词在讨论里指向不同对象，代码和描述也可能冲突。清晰的领域词汇与少量必要的决策记录。术语表不是规格或实现笔记；ADR 要同时满足难逆转、缺上下文会意外、确有取舍。
to-spec
engineering / user		需求已讨论清楚，希望形成可交给后续实现的规格。可交付规格，按配置进入任务追踪并标记 ready-for-agent。原文明确不是新一轮需求访谈；测试接口确认不等于重新 grill 全部需求。通常不写具体文件路径与代码，原型决策片段是例外。
to-tickets
engineering / user		规格较大，需要分成能在独立新会话中完成的任务。逐个可验收的任务、验收条件和明确阻塞边。不是数据库、接口、页面各一张的水平分层；跨全仓机械迁移可用 expand–contract 例外；不关闭或修改父任务。
wayfinder
engineering / user		项目太大、跨多次会话，连决定之间的路线也还看不清。已解决的决定、链接索引和可交给规格阶段的清晰路线。默认产出决定而非直接完成项目；一般一次会话只解决一个决定任务，研究任务例外；不把所有大型已明确任务都当迷雾。
implement
engineering / user		已有一张明确任务或一份范围清楚的规格。已实现、验证、审查并提交的本段工作。不是替需求澄清；原文要求审查和提交，真实操作仍要满足当前会话授权与仓库要求。
implement-spec
engineering / user		规格已有任务图，想让就绪任务并行推进后集成。落在单一集成分支上的整份规格，以及按追踪规则解决的任务。不是把任意任务同时发出去；有阻塞边、有分支同步与合并；草稿 PR 以追踪规则或用户要求为条件。
tdd
engineering / model		接口行为明确，想先用测试固定该行为再实现。与公开行为相符、能在实现重构后继续成立的测试和代码。当前入口原文把重构放到 review 阶段，不放进红绿实现循环；不能从 README 的一般描述推成循环内强制重构。
prototype
engineering / model		纸面讨论无法判断状态规则或界面形式是否合适。可运行的试验原型、所回答的问题及判定结果。不是生产实现；默认内存状态，不先做完整架构、测试与持久化；throwaway 不表示销毁证据。
research
engineering / model		决策依赖外部文档事实，当前没有核对依据。有来源的 Markdown 研究记录。不是凭模型记忆下结论，也不把二手报道当规则来源。
wizard
engineering / model		有 Agent 无法代劳的账号或仪表盘操作。阶段明确、隐藏秘密输入、确认重要操作的 bash 引导脚本。不为 Agent 自己能完成的步骤开向导；不凭空编造仪表盘路径；不自行端到端运行阻塞人工输入的脚本。
diagnosing-bugs
engineering / model		遇到难复现的错误、偶发故障或性能回退。复现信号、被支持的原因、修复与回归证据。反馈环没有建立前不跳到猜原因；敏感输出先脱敏；无有效测试接口位置应如实报告。
triage
engineering / user		有外部错误报告或功能请求，需要判断如何处理。类别、单一状态、已核对事实、简报或缺信息记录。to-tickets 产出的任务已经 ready-for-agent，不应再分诊；外发 AI 分诊记录有原文声明要求，真实外发仍需授权。
code-review
engineering / model		要判断分支或 PR 自某个固定基点以来的改动。分开的规范与需求发现、各轴严重问题。规范通过不代表需求通过；不能用相互抵消的综合评分掩盖一轴失败；当前来源缺规格时明确说明该轴跳过。
codebase-design
engineering / model		接口太复杂，理解一个行为要跳很多文件，或测试越过接口。更清晰的模块接口、位置与可测性判断。深度不是代码行数比；一个适配器不自动构成真实变化位置；接口包含调用者必须知道的约束与错误模式。
improve-codebase-architecture
engineering / user		常改区域难理解、难测试，希望寻找改善机会。候选报告、推荐强度和选中后的设计讨论。调查候选不等于自动重构；报告阶段不先提出具体新接口；默认 HTML 放系统临时目录。
pr
engineering / model		要写一份让审阅者快速理解的 PR 描述。Summary、Evidence、Merge Danger 三部分描述。不是把聊天历史全贴入正文；没有真实执行证据时不补造截图或通过结果。
retro
engineering / user		一轮开发结束，想减少相同错误再次发生。环境改善建议及其证据和优先级。不是重新实现本轮功能，也不把可自动检验的机械规则全写成口头标准。
handoff
productivity / user		要换宿主、目录、同事，或中途分出独立侧任务。可带到新环境的 Markdown 交接文档。不写在当前仓库；保留一手材料的指针，摘要仍是有损二手材料。
teach
productivity / user		要围绕真实学习目的持续学习一个主题。可持续的学习工作区与一系列聚焦课程。不把当下流利感当长期保持；未知基础不能凭空写成已掌握。本包学习 teach 原文规则，不执行上游课程来替你制造历史。
to-questionnaire
productivity / user		决定依赖别人掌握的事实，自己无法回答。可异步填写或会议中使用的发现问卷。访谈发送需求，不反复逼发送者回答他并不知道的主题事实。
wait-what
productivity / user		Agent 的上一条说明跳了上下文，自己跟不上。能接上当前讨论的重新解释。不是继续堆术语，也不凭未确认的背景替用户做决定。
writing-for-agents
productivity / model		技能或 Agent 指令太长、入口含糊、必要规则藏得太深。更可预测的步骤、指针与参考结构。写技能还需读取 SKILL-MECHANICS；条件指针的触发措辞比单纯移文件重要；用户入口不能互相自动触发。
chief-of-staff
in-progress / user		一个会话长时间追求目标，同时改善后续工作环境。目标推进和环境改进的持续编排。试验目录入口，可能变化；不能据此承诺所有宿主都支持调度。
claude-handoff
in-progress / user		要把当前会话交给 Claude 后台继续。脱敏摘要与后台任务。试验且宿主相关；不同于正式 handoff 只交付可携带文档。
loop-me
in-progress / user		想把重复的生活或工作活动变成可交付的工作流规格。workflows 下的逐个规格和工作笔记。试验入口；不强制每个工作流都必须有 AI、定时器或检查点。
setup-ts-deep-modules
in-progress / user		希望包的外部调用和测试都经根入口访问。入口规则、检查命令、示例与导航。试验入口；包可以有多个根入口，不等于只允许一个大 index；模板实现本包不复写。
writing-beats
in-progress / user		已有写作素材，想每次只落一个叙述节拍。逐次增长的文章。试验入口；概念未建立前不能依赖它；不为了用完素材强行续写。
writing-fragments
in-progress / user		还在探索能写什么，尚不该定结构。一个不断积累片段的 Markdown 文件。试验入口；探索与定结构分开；修改前回读，保留原记录。
writing-shape
in-progress / user		素材已收集，想形成有逻辑的正文。独立的文章文档。试验入口；原始素材只读，不挖掘未提供新片段；用户决定文章完成。
git-guardrails-claude-code
misc / model		希望 Claude Code 在危险 Git 命令执行前阻止它们。Claude Code 钩子与配置。misc 已冻结、不在正式插件推广；不把它讲成所有 Agent 的通用防护。
migrate-to-shoehorn
misc / model		TS 测试用很多 as 断言来造部分数据。迁移后的测试代码与核对结果。misc 已冻结；仅测试代码，不用于生产代码。
scaffold-exercises
misc / model		要按现有课程约定建立章节、题目和解释目录。符合该课程工具约定的目录与桩文件。misc 已冻结；依赖具体 ai-hero-cli 约定，不是所有课程的统一目录标准。
setup-pre-commit
misc / model		希望提交前格式化、类型检查和测试能执行。提交前钩子及适用检查。misc 已冻结；没有 typecheck 或 test 脚本时如实省略，不补造命令。

阶段边界的五个选择

按原文顺序：能继续 → 上下文是否无关 → 是否需可携带交接 → 可否独立委派 → 否则再压缩。相邻阶段依赖原始推理时，先考虑继续。

该顺序是思考框架；本页不会清空、委派或压缩任何会话。
